An editor may only offer formatting the page already styles

A rich-text editor embedded in a designed page is not a document editor that happens to be small. It is a hole cut in someone's layout, and everything it permits will eventually appear there. In this system the permitted set is bold, italic, link — because those are the three the page CSS styles — and nothing else.

An unbounded toolbar is how a design gets destroyed by the person it was built for. Not maliciously: the artist wants their exhibition title to stand out, finds a heading button, and uses it. The button was the promise that it would work.

Nothing on the left is a bug. Every one of those marks is a feature working exactly as offered.

If you are reading this in a light theme, switch to dark and look at that panel again. The pasted colours do not know the theme exists: the navy drops to almost unreadable against the dark surface and the highlight burns a hole in the page. Foreign formatting does not merely look wrong — it stops working outright on half the artist palettes, and the site it stops working on is the artist's own.

The toolbar is not the constraint

This is the part that gets built wrong. Shipping a three-button toolbar and calling it bounded leaves every other route wide open: paste carries its own markup and never touches the toolbar, and so do the keyboard shortcuts the library registers by default. The constraint has to live where the formats are defined, not where they are displayed.

1
The format registry
The editor is built from the permitted list, so header, list, blockquote, image, colour, size and align have nothing to land on however they arrive — button, shortcut or paste. It is also what keeps Enter to a plain paragraph: no other block format exists.
2
The paste sanitiser
Paste gets its own gate, because it bypasses everything else. It walks the pasted tree and rebuilds each run from the permitted attributes only, rather than trying to strip the bad ones — a whitelist you construct from cannot be incomplete the way a blacklist can. Embeds carry no copy and are dropped; link hrefs are checked against a scheme allowlist on the way through.
3
The server gate
The client-side restriction protects the design. It is not a control — a request can be made without it. The whitelist that runs on write is the control, and it permits the same four things and nothing else: b, i, a, br.

Worked example: _shared/shell/field-editors.js, field type copyrich. Its COPY_FORMATS constant is stated once and consumed three ways — the format registry, the toolbar, and the paste matcher — so the three can never disagree about what is permitted.

const COPY_FORMATS = ['bold', 'italic', 'link'];

new Quill(host, {
  formats: COPY_FORMATS,                        the registry — not a smaller toolbar
  modules: { toolbar: [['bold', 'italic', 'link']] },
});
q.clipboard.addMatcher(Node.ELEMENT_NODE, ...)   paste, rebuilt from COPY_FORMATS only

The output is an inline fragment, not a block

A copy slot is the inner content of an element the designer already wrote. Most editors think in blocks and hand back <p>…</p>. Nested inside a slot that is itself a <p>, the parser closes the outer tag — and the class that carried the design goes with it.

<p class="lede" data-copy-rich="lede">
  <p>Painter working between London and Margate.</p>   editor emitted a block
</p>

Then the second failure lands on top of the first: the server whitelist has no p, so the tags are stripped to nothing and two paragraphs run silently into one line. <br> is the only break permitted, so that is what a line break has to become. An editor that wraps its content in a block must have that wrapper unwrapped on the way out.

Widening the set is a decision about every page at once

A request for one more format always arrives as a local convenience — one artist, one page, one heading. It is not local. The permitted set is a property of the whole system, and adding to it means every page's CSS now has to style that format, on every artist theme, forever. There is no per-field version of this decision.

The honest answer to "I need a heading here" is almost always that the page needs a heading slot — a field the design owns and styles — not that the copy editor needs a heading button.
