A wider viewport means more columns, never longer lines

This is the one people get wrong when they set out to "make it use the space". The list may widen on a large screen. The form does not — it stays at --adze-width-form, 560px, at every viewport. A 900px-wide text input is worse to use than a 560px one: the caret is a long way from the label, the value floats alone in a field of nothing, and a paragraph of prose runs past the ~75 characters an eye can track back from.

max-width: var(--adze-width-form)
stretched to fill the container

Same fields, same tokens, more pixels spent. The second one is not more capable — it is the same form with a longer journey across it. Space earned by a wide screen is spent on columns, never on line length. On a narrow screen the two are identical, which is the whole point: the divergence only appears once there is room to misuse.

Auto-fit grids, not breakpoints

repeat(auto-fit, minmax(200px, 1fr)) reflows by the width actually available, has no breakpoints to maintain, and degrades correctly at every viewport — including the ones nobody tested. A media query is only warranted for something auto-fit genuinely cannot express: the touch-target height bump at 640px in tokens/spacing.css is the whole list. Every media query added after that is a future inconsistency, because the next person will add theirs at a different number.

Drag the bottom-right corner of the panel below. Four short fields go 4 → 2 → 1 without a single query. 

display: grid;
grid-template-columns: repeat(auto-fit, minmax(var(--adze-col-min), 1fr));
gap: var(--adze-space-4);

Layout is derived from field role, not declared per project

A field's role decides where it lands. Nothing in a schema says "put this in column two" — the schema says what the field is, and the layout follows. That is what lets a brand-new project get a good layout from a schema that says nothing about layout at all.

identity
Title, slug
First, on its own line. It names the thing; nothing shares its row.
media
Image, upload
Immediately after identity. An artist should see the picture before they see a text box.
short
Year, medium, dimensions, price
Packed into one auto-fit group at minmax(var(--adze-col-min), 1fr), so related metadata shares a row.
long
Description, statement
Full width of the form column — which is 560px, not the viewport.
tags
Categories, collections
Full width, below the long fields. Chips wrap; they do not need a column.
the whole form, derived

The escape hatches are deliberately tiny — two keys, not a layout DSL. If you reach for a third, the role is wrong.

field       { "role": "short" }                    packed into the auto-fit group
field       { "role": "short", "width": "full" }   the one per-field override
collection  { "list": "grid" }                     or "rows" — the one per-collection override

The corollary is not optional. A grid of pictures requires an image tier sized for cards. Serving the 2000px display image into a 200px slot is how a gallery of 32 works becomes a 25 MB page load — on a phone, on the artist's own data. Cut a card tier at roughly 400px and point the grid at it. If there is no card tier yet, that is the work; it is not a detail to follow later.

One spacing owner per stack

A container using gap whose children also carry margin-bottom gets both. Nothing errors — the form simply runs looser in one place than another, and the two drift further apart every time someone tunes one of them. This is a live bug class in this codebase: .as-feedback uses a flex gap, so its .af-field children have their bottom margin zeroed; without that the same form ran 32px there against 20px in the content admin.

gap 16 + margin-bottom 16 = 32px
gap owns it, margin zeroed = 16px

Pick one owner and say so where the container is defined. The trailing margin under the last child is the same bug wearing a hat — it is why a stack so often sits lower in its box than it sits in its own padding.
